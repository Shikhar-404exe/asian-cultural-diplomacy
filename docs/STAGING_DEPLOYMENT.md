# Vercel & Supabase Staging Deployment Guide

**Author:** DevOps & Cloud Engineering  
**Target Environment:** Vercel Hosting + Supabase PostgreSQL & Storage  
**Document Status:** Ready for Execution  

---

## 1. Three-Tier Isolated Environment Architecture

To protect production integrity, development, staging, and production environments are strictly separated across all dimensions:

| Dimension | Development (Local) | Staging (Pre-Release) | Production (Live) |
|---|---|---|---|
| **Host** | Local Machine (`localhost:3000`) | Vercel (`staging-acd.vercel.app`) | Vercel (`asianculturaldiplomacy.org`) |
| **Database** | SQLite (`prisma/dev.db`) | Supabase Staging PostgreSQL | Supabase Production PostgreSQL |
| **Storage** | Local Filesystem (`/public/uploads`) | Supabase Storage (`staging-media`) | Supabase Storage (`production-media`) |
| **Admin Account** | `founder@asianculturaldiplomacy.org` | `staging-founder@asianculturaldiplomacy.org` | Genuine Founder Account |
| **Data Scope** | Synthetic test data | Sanitized staging test data | Real editorial articles & real readers |
| **Access Gate** | Local Wi-Fi subnet | Vercel Deployment Protection / Password | Open Public Internet |

> [!CAUTION]
> Development and staging secrets must **never** be shared with production. Never execute test seeds or automated destructive test suites against production databases.

## 2. Setting Up Supabase for Staging

1. Create a Supabase project named `ACD-Staging`.
2. In **Storage**, create a new public bucket:
   - Name: `media`
   - Public bucket: **Enabled** (read access for website visitors).
   - Allowed MIME types: `image/jpeg`, `image/png`, `image/webp`.
3. In **Project Settings > API**, retrieve:
   - `Project URL` (`NEXT_PUBLIC_SUPABASE_URL`)
   - `anon public` key (`NEXT_PUBLIC_SUPABASE_ANON_KEY`)
   - `service_role secret` key (`SUPABASE_SERVICE_ROLE_KEY`)
4. In **Project Settings > Database**, retrieve the connection strings:
   - Connection Pooling URI (`DATABASE_URL`) on port `6543`.
   - Direct URI (`DIRECT_URL`) on port `5432`.

## 3. Configuring Vercel Staging Environment

### Option A: Connecting via Git (Recommended)
1. Push this repository to GitHub or GitLab.
2. In the [Vercel Dashboard](https://vercel.com), click **Add New > Project** and select the repository.
3. In **Build and Output Settings**:
   - Framework Preset: **Next.js**
   - Build Command: `prisma generate && next build`
   - Install Command: `npm install`
4. In **Environment Variables**, select the **Preview / Staging** scope and add the keys below:

```env
# Application
NODE_ENV="production"
NEXT_PUBLIC_APP_URL="https://staging-acd.vercel.app"
SESSION_SECRET="generate_random_64_character_hex_secret_for_staging"

# Database (Supabase Staging)
DATABASE_URL="postgresql://postgres:[PASSWORD]@[STAGING-HOST]:6543/postgres?pgbouncer=true"
DIRECT_URL="postgresql://postgres:[PASSWORD]@[STAGING-HOST]:5432/postgres"

# Administrator Provisioning
ADMIN_EMAIL="staging-founder@asianculturaldiplomacy.org"
ADMIN_PASSWORD="StagingSecurePassword2026!"
ADMIN_NAME="Founder & Director (Staging)"

# Supabase Storage
NEXT_PUBLIC_SUPABASE_URL="https://[YOUR-STAGING-PROJECT].supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="your-staging-anon-key"
SUPABASE_SERVICE_ROLE_KEY="your-staging-service-role-key"
SUPABASE_STORAGE_BUCKET="media"

# Gmail Notifications (Optional for Staging)
GMAIL_USER="staging-founder@asianculturaldiplomacy.org"
GMAIL_CLIENT_ID=""
GMAIL_CLIENT_SECRET=""
GMAIL_REFRESH_TOKEN=""
```

### Option B: Deploying via Vercel CLI
```bash
# 1. Install Vercel CLI
npm install -g vercel

# 2. Login to Vercel account
vercel login

# 3. Deploy to staging
vercel --prod=false
```

## 4. Staging Verification Protocol

Once deployed to Vercel:

1. **Verify Database Push**: Run schema sync against the staging database:
   ```bash
   DATABASE_URL="postgresql://..." npx prisma db push
   ```
2. **Access Staging URL**: Open the preview URL generated by Vercel.
3. **Verify Public Navigation**: Confirm that no "Founder Portal" links appear in the header or footer.
4. **Log in as Administrator**: Visit `/admin/login` and log in with the staging founder credentials.
5. **Verify Cloud Image Upload**: Upload a test artwork image to `/admin/media`. Confirm that the image URL points to Supabase CDN (`https://[PROJECT].supabase.co/storage/v1/object/public/media/...`).
6. **Verify Server Autosave**: Write a test article in `/admin/blogs/new` and observe `Saved to Cloud`.
